A state-of-the-art, full-stack, real-time trending topic detection system specifically optimized for bilingual processing of **English and Somali** social media data. This repository contains the complete implementation of the Final Year Project (FYP), structured to present an academically rigorous dual-model comparative workflow (Latent Dirichlet Allocation vs. BERTopic) and a high-performance production-ready microservice architecture.

---

## 📌 Project Overview

Digital platforms are a primary forum for public discourse, yet regional and low-resource languages like Somali are often excluded from modern NLP tools. This system addresses this gap by offering a fully integrated, real-time, bilingual ingestion and topic-modeling pipeline. It utilizes **LDA** as a statistical baseline and deploys **BERTopic** as an advanced embedding-based transformer architecture to extract, score, and track digital trends as they emerge.

### 🌟 Key Capabilities
- **Bilingual Processing Engine:** Native, concurrent handling of English and Somali social media data. It bridges the low-resource gap via a custom-curated Somali stopword dictionary (140+ terms) and unified cross-lingual embedding spaces.
- **Dual-Model Experimental Design:** Side-by-side implementation of Latent Dirichlet Allocation (LDA baseline) and BERTopic (advanced production) to support academic benchmarking.
- **Real-Time Data Ingestion:** Background stream crawling connecting to the Twitter API v2, fortified with a duplicate-filtering engine and an automated **Quota Shield** to prevent API rate depletion.
- **Dynamic Trend Scoring:** Aggregates topic velocity, document volume, and user engagement metrics (likes + retweets) to rank trends dynamically.
- **Interactive Serve Layer:** Serve dynamic intertopic maps generated by `pyLDAvis` (LDA) and `Plotly` (BERTopic) directly into the dashboard interface.
- **Security & Notification Suite:** Comprehensive user system including secure JWT logins, Google OAuth, 2-Step Verification (2FA via email), user preference toggles, daily email digests, and immediate trend spike alerts.

## 🧠 Scientific Methodology & Core Models

### 1. The Baseline: Latent Dirichlet Allocation (LDA)
LDA is a generative probabilistic model representing text documents as mixtures over latent topics, and topics as probability distributions over words.
- **Mathematical Foundations:** Regulated by Dirichlet hyperparameters $\alpha$ (document-topic density) and $\beta$ (topic-word diversity).
- **Somali Preprocessing:** Text undergoes lowercase conversion, regex URL/mention stripping, and filtration against a custom dictionary of **140+ Somali stopwords** (e.g., *waa*, *iyo*, *aad*, *balse*, *waxa*) alongside English stopwords.
- **Tuning:** A grid search iteratively adjusts the topic count ($K \in [5, 8, 10, 12]$) to optimize the Coherence Score ($C_v$) and minimize perplexity.

### 2. The Production Standard: BERTopic
BERTopic leverages modern Transformer models to yield context-aware embeddings, bypassing the Bag-of-Words semantic limitations of LDA.
- **Embedding Generation:** Uses the multilingual `paraphrase-multilingual-MiniLM-L12-v2` Sentence-Transformer to embed English and Somali tweets into a shared $384$-dimensional semantic space.
- **Dimensionality Reduction:** Projects vectors into $5$-dimensions using UMAP with a cosine metric, preserving local neighborhoods.
- **Density Clustering:** Groups embeddings using HDBSCAN with an adaptive threshold scaled automatically to corpus size:
  $$\text{min\_cluster\_size} = \max(3, \min(10, N_{\text{docs}} // 5))$$
- **Topic Representation:** Extracts distinctive words using Class-Based TF-IDF (c-TF-IDF):
  $$W_{c,i} = \text{tf}_{c,i} \times \log\left(1 + \frac{A}{\text{df}_i}\right)$$

### 3. Dynamic Trend Scoring
The system prioritizes emerging trends by scoring each topic cluster based on its volume and social user interactions (likes & retweets):
$$\text{Trend Score} = 0.6 \times \text{Volume Component} + 0.4 \times \text{Engagement Component}$$
- **Volume Component:**
  $$\text{Volume Component} = \min\left(\frac{N_{\text{documents}}}{100.0}, 1.0\right) \times 100$$
- **Engagement Component:**
  $$\text{Engagement Component} = \min\left(\frac{\text{Likes} + \text{Retweets}}{\max(\text{Corpus Max Engagement}, 1)}, 1.0\right) \times 100$$

## ⚖️ Model Comparison (8-Criteria Academic Benchmarking)

During evaluation, both models are assessed side-by-side. The results of this scientific audit are displayed dynamically in the system's "Model Comparison" dashboard screen:

| Criterion | Baseline Model (LDA) | Production Model (BERTopic) |
| :--- | :--- | :--- |
| **Architecture** | Generative Probabilistic (Statistical) | Modular (Context Transformers + UMAP + HDBSCAN) |
| **Preprocessing** | Heavy required (Lemmatizing, Stopword stripping) | Minimal required (Preserves sentence context) |
| **Semantic Depth** | Low (Reconstructs from word frequency counts) | High (Encodes rich contextual representations) |
| **Bilingual Capability** | Moderate (Requires separate stopword pipelines) | High (Native joint English/Somali embedding space) |
| **Short-Text Performance**| Poor (Suffers from sparsity on 280-char tweets) | High (Leverages contextual sub-word features) |
| **Topic Assignment** | Soft Clustering (Documents have shared distribution) | Hard Clustering (Deterministic assignments) |
| **Real-Time Suitability** | Low (Retraining complexity limits velocity) | High (Supports Dynamic Topic Modeling updates) |
| **Compute Demands** | CPU-Bound (Moderate memory usage) | GPU-Bound (High demands during embedding steps) |

## 🚀 Getting Started

### Prerequisites
- **Python 3.9+** (For the FastAPI Backend server)
- **Node.js 18+** (For the React Frontend dashboard)
- **MongoDB** (Local instance running on `localhost:27017` or MongoDB Atlas URI)

---

### 1. Backend Server Setup (`api/`)

1. Clone this repository and navigate to the project's root folder:
   ```bash
   cd RealTime-Trending-Topic-Detection-System
   ```

2. Create and activate a Python virtual environment:
   ```bash
   python -m venv venv
   # On Windows:
   venv\Scripts\activate
   # On macOS/Linux:
   source venv/bin/activate
   ```

3. Install the optimized backend package requirements:
   ```bash
   pip install -r requirements.txt
   ```

4. Configure your Environment Variables by creating a `.env` file in the root directory:
   ```env
   MONGODB_URL=mongodb://localhost:27017
   DATABASE_NAME=trending_topics
   SECRET_KEY=YOUR_SUPER_SECRET_JWT_SIGNING_KEY
   
   # Optional: Twitter API credentials (dev mode handles empty values gracefully)
   TWITTER_BEARER_TOKEN=YOUR_TWITTER_V2_BEARER_TOKEN
   
   # Model Training Configurations
   BERTOPIC_MIN_CORPUS_SIZE=20
   BERTOPIC_TRAIN_INTERVAL_MINUTES=30
   COMPARISON_INTERVAL_HOURS=168
   
   # Optional: Email Service Configurations (for 2FA, Alerts & Digests)
   SMTP_ENABLED=true
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=587
   SMTP_USER=your_email@gmail.com
   SMTP_PASSWORD=your_app_password
   SMTP_FROM=noreply@visiontech-trends.com
   SMTP_USE_TLS=true
   ```

5. Initialize the database and launch the FastAPI server in reload (development) mode:
   ```bash
   cd api
   uvicorn app.main:app --reload
   ```
   *The FastAPI server will boot up successfully and expose endpoints at `http://localhost:8000`. You can inspect the interactive OpenAPI Swagger docs at `http://localhost:8000/docs`.*

---

### 2. Frontend Dashboard Setup (`dashboard/`)

1. Open a new terminal instance and navigate to the `dashboard/` directory:
   ```bash
   cd RealTime-Trending-Topic-Detection-System/dashboard
   ```

2. Install the frontend Node packages:
   ```bash
   npm install
   ```

3. Run the development server:
   ```bash
   npm run dev
   ```
   *The dashboard application will start up at `http://localhost:5173`. It is pre-integrated to communicate directly with your local FastAPI server at port 8000.*
